## Componentes que profundizar primero

**VideoLingo: checkpoints de revisión.** Leer `review_terminology` y `review_translation` muestra pausa → edición → validación → continuación, con conservación del origen y filas. `_4_1_summarize.py` evita sobrescribir terminología ya editada. Studio necesita ese patrón en la frase ASR, no la traducción ni Excel. Integración propuesta: error estructurado con audio_sha256/texto/modelo/escena; vista de escucha; aprobación de discrepancia específica; continuación usando la misma voz. Alternativa: seguir corrigiendo manualmente tiempos, insuficiente cuando el preview completo aborta. Prueba: fallo de una frase no impide escuchar las demás, editar el audio/texto invalida la revisión; cero TTS al aceptar una transcripción. Dificultad media; sin nuevas dependencias. Caché VideoLingo y sus tests se releyeron, pero GST-013 ya la resuelve en nuestro stack.

**Carousel Generator: documento y operaciones de página.** `DocumentSchema` separa config/slides; `slide-menubar.tsx` usa swap/insert/remove. La integración exige extender contratos, UI, renderer, URLs de artefactos y hashes de release; no basta quitar una validación de longitud. El generador tiene TODOs de exportación y dependencias antiguas: conservar JPG/Sharp del servidor. Alternativa: varias plantillas fijas de cuatro páginas, menor coste pero poca edición. Prueba: 3/4/6 páginas, insertar/reordenar/quitar, recursos/claims conservados y aprobación invalidada al cambiar orden. Dificultad media; crecimiento lineal de render, sin tarifa nueva de IA si se edita contenido existente.

**MoneyPrinterTurbo: persistencia de artefactos y errores por etapa.** `task_artifacts.py` escribe temporal/fsync/replace; sus tests conservan campos y protegen JSON inválido. `task.py` distingue failed_stage, conserva referencias de ejecuciones pagadas y evita repetir pedidos inciertos. Adoptar patrón propio en Creative/ASR; no importar Python/MoviePy ni su cola. Alternativa: migrar todo a un motor durable, desproporcionado. Prueba: interrupción antes/después de respuesta deja JSON legible, estado clasificable y ninguna repetición automática de proveedor incierto. Dificultad media; disco local, no servicio añadido.

LTX complementa la selección de tomas; AiToEarn/Postiz complementan contratos de recuperación. waoowaoo sirve de patrón conceptual de operación/intent; su licencia y complejidad desaconsejan extracción literal apresurada.

## Licencias y APIs: límites de la recomendación

Se releyeron licencias raíz y se verificaron rutas al commit. MIT y Apache requieren conservar avisos aplicables; cualquier adaptación futura debe registrar origen/modificaciones. Postiz es AGPL-3.0, no MIT. waoowaoo es Elastic License 2.0: [texto oficial](https://www.elastic.co/licensing/elastic-license) impone restricciones de servicio alojado y avisos. No se ha realizado una evaluación jurídica de una combinación de código concreta; aquí se propone código propio inspirado en patrones, no forks.

Short Video Maker usa Remotion, cuya [licencia independiente](https://www.remotion.dev/docs/license) no queda sustituida por MIT del repositorio. Apache de LTX no licencia automáticamente pesos/LoRA; no se descargarán modelos. Fonts, stock, música, voces y consentimiento requieren revisión por recurso. No se ha recomendado incorporar ninguno de esos activos ni se presume gratuidad de operación local.

[TikTok: Content Sharing Guidelines](https://developers.tiktok.com/doc/content-sharing-guidelines) se consultó de nuevo: restricciones para clientes no auditados y herramientas limitadas a cuentas del propio equipo hacen improcedente proponer Direct Post privado como sustitución automática de Buffer. Meta Content Publishing no fue accesible mediante web en esta pasada; permisos y formatos efectivos de la cuenta siguen pendientes. Ninguna recomendación amplía publicación por API sin comprobar primero capacidades oficiales/cuenta/contrato del intermediario.

### Meta y TikTok: requisitos separados de publicación

Para TikTok, [Marketing API y Organic API son productos distintos](https://business-api.tiktok.com/gateway/docs/index?doc_id=1735712062490625&language=ENGLISH). La [autorización de anunciante](https://business-api.tiktok.com/gateway/docs/index?doc_id=1738373141733378&language=ENGLISH) exige la aplicación/cuenta de desarrollador y permisos pertinentes de Business API. Tener el canal en Buffer no demuestra advertiser_id, aplicación Ads ni acceso a reportes. Todo eso queda NO VERIFICADO para nuestra cuenta.

Reutilizar un video publicado como Spark Ad exige [autorización de contenido para Spark Ads](https://ads.tiktok.com/help/article/how-to-use-content-suite-to-create-and-launch-spark-ads?lang=en). No basta conocer el enlace del post. Igualmente, promocionar una publicación Meta requiere verificar identidad/activos/permisos publicitarios; no basta guardar su URL. Verificar restricciones del objetivo, categoría, país, destino, formatos y derechos al preparar el caso concreto; no se proponen reglas de presupuesto mínimo inventadas.

Meta documenta [atribución en Insights](https://www.postman.com/meta/facebook-marketing-api/request/5wdl62t/attributionsetting). Se debe registrar la configuración realmente admitida por la versión elegida; no copiar sin validación todas las ventanas de un ejemplo histórico. Ningún resultado de esta auditoría prueba ventas incrementales.

### Arquitectura y piloto recomendado

Studio conserva marcas/campañas/creativos/versiones y sigue publicando orgánico por n8n. Un módulo Ads del backend añade conexiones permitidas, borradores publicitarios, autorizaciones de gasto, operaciones y métricas pagadas; guarda referencias de credenciales, no secretos en snapshots. SDK Meta se encapsula detrás de adaptadores de lectura/escritura separados. n8n programa una lectura pasando IDs internos; no recibe permiso de activación por tener permiso orgánico.

**Primera fase propuesta, exclusivamente lectura:** verificar la cuenta y `ads_read` de la app existente; permitir una sola cuenta; GET de cuentas accesibles y metadatos (id, name, account_status, currency, timezone_name), campañas/adsets/anuncios y siete días completos de insights sin reportes asíncronos que requieran POST. Paginación con límite, reintentos solo para GET transitorio, límites de concurrencia, validación de host y logs redactados. Comparar cifras con Ads Manager con el mismo período, zona, nivel y atribución. Mostrar datos ausentes como ausentes. Interceptor de prueba debe rechazar POST/PATCH/DELETE y diagnóstico del SDK debe estar desactivado. No incluir token en parámetros visibles/logs/errores/archivos exportados.

**Fase posterior solo propuesta:** borrador ligado a versión → aprobación editorial y derechos para Ads → autorización de configuración y gasto por dueño → creación remota en pausa en todos los niveles aplicables → lectura de confirmación → activación explícita. Cambios en destino, pieza/texto, segmentación, identidad, presupuesto o fechas invalidan la autorización correspondiente. Un timeout posterior a envío bloquea repetición hasta reconciliar IDs/resultado. No se ejecutó esta fase.

No se recomienda migrar toda la base. JSON serializado sirve para el lector inicial de un proceso; si la fase de escritura exige varios workers/transacciones entre operaciones, evaluar entonces un ledger transaccional acotado (por ejemplo SQLite), con migración/pruebas, no una reescritura global.

**Continuación exacta:** revisar en la app existente casos de uso/Marketing API, modo, estado/nivel de `ads_read`, cuenta `act_…` y asignación al usuario/sistema. El usuario solo debe facilitar el ID de la cuenta y datos no secretos o habilitar el navegador; si hay que renovar tokens/conceder permisos, solicitar intervención para ese paso. Sin eso puede implementarse posteriormente el piloto con fixtures, pero no declararse validado contra Meta. Tareas ejecutables y aceptación: GST-028–032 en `mejoras-studio.md`.
